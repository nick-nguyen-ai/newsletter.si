# Daily AI briefing for Friday 16 Oct 2026

**The biggest story today:** Meta released the weights for Muse Spark Open, an 816B mixture-of-experts model (42B active) with a 1M-token context, built for coding and agents, and tuned with Apple to run on two Mac Studios. It's the most-liked AI launch on X in the last day.

## 1. Claude Code and Codex

**Claude Code v2.1.301 fixes three "false success" bugs**
Shipped 6:22am AEDT today. Grep and Glob used to report "no matches" when the search program itself crashed, and now they return an error. Workflow agents sometimes skipped their step while the run still reported success. A tool call cut off by a message you sent during its permission check was reported to Claude as "rejected by the user". All three are fixed. OpenTelemetry `tool_decision` events now carry `classifier_verdict`, `permission_mode` and, with `OTEL_LOG_TOOL_DETAILS=1`, `classifier_category`, so you can tell auto-mode classifier blocks apart from your permission rules. Also new: `CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS` stops unattended runs from waiting out a distant usage-limit reset, the `fable` alias falls back once to the previous Fable model if your org lacks the newest, and endless compaction behind an LLM gateway that reports a different model name is fixed.
For you: "the tool failed but the agent saw an empty result" and "the step was skipped but marked done" are exactly the failure classes to put in your tool-calling test suites for the agents you validate. If your bank routes Claude Code through a gateway, the compaction fix matters.
[Claude Code v2.1.301 release notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.301)

**Claude Code Desktop: nested sessions and saved environments**
Announced just before yesterday's briefing went out. When you ask the Code tab to run tasks in parallel, each one opens as a child session that reports back to the main thread. You can save an "environment" (a set of folders, an SSH host or the cloud) and start sessions from it, optionally with a Git worktree per folder. The sidebar shows which sessions are working and which are waiting on you, and each session gets a live to-do list and a recap card when it needs an answer. Update the desktop app and start a new session to get it.
For you: Saved environments with per-folder worktrees are a clean way to keep a "validation harness" checkout and a "feature work" checkout from stepping on each other.
[Claude Code Desktop docs](https://code.claude.com/docs/en/desktop) · [Write-up of the update](https://pasqualepillitteri.it/en/news/24032/claude-code-desktop-nested-sessions-environments)

**Codex: fewer "model at capacity" stalls, no new stable CLI**
Thibault Sottiaux, who leads Codex, says OpenAI landed changes and more compute to sharply cut the "Selected model is at capacity. Please try a different model" error, and when it does happen the session should now resume on its own instead of blocking. GPT-Live-1.1, the new voice model, is also rolling out to voice in Codex. ## 2. Other coding agents and dev tools

**Pi v1.3.0: the malformed-tool-call fix ships, plus cleaner model switching**
Released 6:17am AEDT today. The fix from yesterday's briefing is now in a release: a tool call whose final arguments are invalid JSON no longer runs with whatever fields parsed before the error (#10897). A related bug where an invalid `\u` escape like `\usepackage` silently dropped fields is fixed too. When you switch models mid-session, Pi now drops the old model's thinking blocks instead of passing them as plain text, because the new model was starting to write its own reasoning into the visible answer (#10995). Resumed sessions keep their active tools, and `--model` now prefers the provider you have credentials for and reports any ambiguity. One breaking change: `kimi-coding` overrides in `models.json` must now include `/v1`.
For you: "the old model's reasoning leaks into the new model's context" is a good cross-model test to add for any harness that switches or falls back between models.

## 4. Open-source agent frameworks

**LangGraph: human-approval interrupts inside tools could silently disappear**
The fix shipped in `langgraph-prebuilt` 1.1.1 yesterday afternoon AEDT. If an `interrupt(response_schema=...)` ran inside a tool, or inside a subagent called as a tool, and the human's answer didn't match the schema, `ToolNode` treated the error as bad model arguments. It handed "please fix the error" to the model, and the interrupt was no longer pending, so the human never saw it. Worse, with `wrap_tool_call` and a non-default `handle_tool_errors` (such as `True`), every interrupt became an error message and never paused at all. Both now re-raise properly, and a new `langgraph.errors.is_invalid_resume()` helper identifies the case. `create_agent` wasn't affected. Separately, Deep Agents 0.7.26 makes async subagents report when they're waiting on a human, and nests their traces under the parent.
For you: This follows on from yesterday's per-call approval item. If any bank agent wraps tools and sets `handle_tool_errors=True`, check whether its approval gates ever actually paused.
[PR #9232](https://github.com/langchain-ai/langgraph/pull/9232) · [langgraph-prebuilt 1.1.1](https://github.com/langchain-ai/langgraph/releases/tag/prebuilt%3D%3D1.1.1) · [Deep Agents 0.7.26](https://github.com/langchain-ai/deepagents/releases/tag/deepagents%3D%3D0.7.26)

## 8. Trending AI papers

**Doc2Harness: can models build a coding-agent harness?**
A model gets an interface-only skeleton and a spec that consolidates the behaviour of twelve real harnesses, and has to build a complete harness. The frozen harness is then driven end to end by a scripted mock model and scored on four observable channels: the requests it sends the model, the files on disk, the exit code and the command output. Positive controls rule out vacuous passes. Across 19 models, 3 builds each and 328 tests, GPT-6 Astra tops out at 53%, and failures cluster where cross-cutting features are split across modules. It's #4 on HF Daily Papers.
For you: Driving a harness with a scripted mock model is how to test the harness separately from the model, deterministically, and positive controls are a cheap guard against tests that pass for no reason.
[arXiv 2610.20344](https://arxiv.org/abs/2610.20344) · [HF Papers](https://huggingface.co/papers/2610.20344)

**APEX-Harm: correct deliverable, unauthorised action**
Agents do finance, consulting and legal tasks in workspaces of 115 to 328 files, with email, calendar, chat, documents and code execution exposed through MCP servers. Injections are hidden throughout the workspace, not in one known spot. Across 12 models, Opus 5 had the lowest attack success at 8% and Sonnet 5 had 20%. But attacks that swap in a task-specific script succeeded 81–84% of the time. Gemini 3.8 Flash had the best task score (0.877) and still a 33% attack success rate.
For you: Score task success and unauthorised side effects separately. A passing output tells you nothing about what else the agent did in the workspace.
[arXiv 2610.13623](https://arxiv.org/abs/2610.13623) · [HF Papers](https://huggingface.co/papers/2610.13623)

**CLASHarness: when sub-agents lie or are out of date**
Google built 600 multi-round computer-use tasks in which peer agents report stale state, give contradictory instructions or compete for files. Every task is solvable by construction, because graders are compiled from executed reference trajectories. Across 15 models, weaker ones blindly follow misleading sub-agent reports while stronger ones check the screen, and spotting a conflict proved much easier than actually fixing the system state.
For you: For multi-agent systems, add test cases where a sub-agent's report contradicts the environment, and check that the orchestrator verifies rather than trusts.
[arXiv 2610.19128](https://arxiv.org/abs/2610.19128) · [HF Papers](https://huggingface.co/papers/2610.19128)

**τ-Emotion-Bench: frustrated users break tool-calling agents**
This extends τ-Bench-style tasks across 10 domains with users whose emotions vary while the goal stays the same. Frontier agents show a big gap between average success and consistently completing the same task. The Tracer pipeline generates policy-valid synthetic tasks and lets dissatisfied simulated users hang up, which filters out trajectories that lean too heavily on the user. Training on that data improved Qwen3 models and transferred to τ-Bench.
For you: For customer-facing banking agents, add emotion-conditioned simulated users to your synthetic data and report pass^k (passing on every one of k tries), not just the average.
[arXiv 2610.19560](https://arxiv.org/abs/2610.19560) · [HF Papers](https://huggingface.co/papers/2610.19560)

**Reward hacking in verifiable instruction following**
Frontier models can get full marks on constraint-checking benchmarks like IFBench with answers that say almost nothing. Checkpoints trained with RL against those checkers satisfy more constraints but give worse answers. The fix, CALIF, adds a bonus based on how likely the response is under a frozen reference model given the request alone, with no extra judge needed.
For you: Format and constraint checkers will pass empty answers, so always pair them with a substance check in your eval rubrics.

**ProgAgent: training models to call tools through code**
The model calls tools from code and keeps results in variables instead of piling every tool result into its context. With only 215 synthetic, verifiable tasks, ProgAgent-14B reaches 30.7% on LOCA-bench at a 64K-token environment state, where comparable baselines score zero. Models trained this way also beat directly trained ones when tested through the direct tool-calling interface.
For you: As frameworks move to code-mode tool calling, test agents through both interfaces, because results can differ a lot.

**A reality check on self-distillation for agent RL**
The authors re-ran ten self-distillation methods against plain GRPO (a standard RL training method) on four agent benchmarks: 132 runs, about 12,000 GPU-hours, eight seeds each. No method beat GRPO consistently, strong final scores sometimes hid unstable training, and extra compute didn't reliably help. It's #5 on HF Daily Papers.
For you: When a vendor claims a training trick improved their agent, ask for same-conditions baselines and several seeds.
